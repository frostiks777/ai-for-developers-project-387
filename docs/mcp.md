# MCP-серверы

Этот документ описывает MCP-серверы, подключённые через `opencode.jsonc`, и правила работы с ними.

## Текущие MCP

| Имя | Тип | Назначение | Команда / URL |
|---|---|---|---|
| `shadcn` | local | Доступ к каталогу shadcn/ui: список компонентов, метаданные, установка через натуральный язык. Использует `components.json` в корне проекта. | `npx -y shadcn@latest mcp` |

Конфигурация — в корневом `opencode.jsonc`, блок `"mcp"`.

> [!IMPORTANT]
> Пакет MCP-сервера называется `shadcn`, а MCP запускается подкомандой `mcp`.
> Имя `@shadcn/ui/mcp` **невалидно** — npm отвечает `EINVALIDPACKAGENAME`,
> процесс молча падает, а opencode показывает `MCP error -32000: Connection closed`.
> Проверка перед подключением: `npx -y shadcn@latest mcp --help`.

## Когда используется

- Агент сам решает, нужен ли MCP для текущей задачи, по триггер-фразам в `description` инструментов MCP.
- Если mcp-сервер не отвечает (timeout, сеть, ошибка запуска пакета) — **fallback на встроенные инструменты**:
  - `webfetch` / `websearch` для документации и поиска.
  - `browser.*` для интерактивных страниц.
  - `read` / `glob` / `grep` для локального кода.

## Когда **не** использовать

- Секреты, прод-данные, доступ к закрытым реестрам — **никогда**. MCP-серверы получают те же права, что и основной агент (см. `AGENTS.md` → `Safety gates`).
- Команды MCP, требующие авторизации через токены (`GITHUB_PERSONAL_ACCESS_TOKEN` и т.п.) — подключать только если в этом есть явная задача и пользователь дал токен.

## Как добавить новый MCP

1. Проверить, что сервер доступен и работает (например, через `npx <pkg> --help` или `npm info <pkg>`).
2. Проверить, что он не требует платных ключей или доступа к закрытым API.
3. Добавить запись в блок `"mcp"` в `opencode.jsonc` в формате `McpLocalConfig` или `McpRemoteConfig` (см. схему `https://opencode.ai/config.json`).
4. Дополнить таблицу выше: имя, тип, назначение, команда.
5. Закоммитить отдельным коммитом: `chore(agents): add mcp <name>`.

## Troubleshooting

| Симптом | Причина | Что делать |
|---|---|---|
| `MCP error -32000: Connection closed` | Процесс сервера умер сразу после старта. Чаще всего — пакет не существует/невалиден или нет сети | Прогнать команду из `command` в терминале вручную. Для shadcn это был кейс `@shadcn/ui/mcp` → `EINVALIDPACKAGENAME` |
| MCP-инструменты не видны в каталоге | Ошибка запуска пакета (timeout, network) | Проверить `npx -y <pkg>@latest` в терминале вручную. Если внешняя сеть недоступна — временно поставить `"enabled": false` |
| Tool call MCP валится с timeout | Сервер медленный или зависает | Увеличить `"timeout"` в `opencode.jsonc` (по умолчанию 5000 мс) или `"type": "remote"` с CDN |
| MCP отдаёт устаревшие данные | Сервер использует кэш | Перезапустить opencode (kill + start), `npx` форсирует свежий пакет благодаря `@latest` |
| Конфликт версий пакета | `@latest` дрейфует | Зафиксировать версию в команде: `["npx", "-y", "shadcn@3.1.0", "mcp"]` |
