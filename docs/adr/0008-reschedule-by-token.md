# ADR 0008: Перенос брони по токену-ссылке

## Status

Accepted — 2026-09-23.

## Context

Спека (`docs/code_artifact.md`, §3 «Экран 3») упоминает «ссылку на отмену **или перенос**». [ADR-0006](0006-cancellation-by-token.md) реализовал отмену по токену, но перенос оставил нереализованным. Гостю нужен способ передвинуть встречу на другое свободное время без создания новой брони.

## Decision

Гость переносит бронь по тому же токену, что и отменяет.

- **Чтение.** `GET /api/bookings/by-token/:token` возвращает `BookingWithSlot` (текущее время) по capability-токену; `404` — если токен неизвестен. Токен не показывается в списках `/dashboard`.
- **Перенос.** `POST /api/bookings/reschedule` с телом `{ token, slotId }`: обновляет `bookings.slotId` существующей брони. Старый слот освобождается, новый занимается (уникальность гарантирует `UNIQUE(slotId)`, [ADR-0003](0003-unique-slot-booking.md)). Статусы: `200` с обновлённой бронью, `404` — токен/слот не найден, `400` — слот в прошлом или в пределах `minNotice`, `409` — целевой слот уже занят.
- **Идемпотентность.** Перенос на тот же слот — успешный no-op (без `UPDATE`).
- **UI.** Страница `/reschedule/:token`: показывает текущее время, календарь и свободные слоты, кнопка «Перенести сюда» на каждом. После успеха — новое время. Ссылка «Перенести» добавлена на экран успеха рядом со ссылкой отмены.
- **Схема БД не меняется** — перенос это `UPDATE bookings.slotId`.

## Consequences

- (+) Гость сам меняет время, слоты не «зависают» и не дублируются.
- (+) Переиспользует токен-модель [ADR-0006](0006-cancellation-by-token.md) и `UNIQUE(slotId)`; новой миграции нет.
- (+) Старый слот освобождается автоматически (бронь ссылается на один слот).
- (−) Токен в URL `/reschedule/:token` — те же риски capability-ссылки, что в ADR-0006.
- (−) Нет уведомлений (email/telegram) о переносе — уведомлений в проекте нет вовсе.
- (−) Перенос доступен в пределах `minNotice`-правил: на слот ближе 2 часов перевести нельзя (осознанное ограничение).

## Alternatives considered

- **Удалить бронь и создать новую при переносе.** Отклонено: новый `id` и токен, лишние гонки, теряется непрерывность брони; `UPDATE slotId` проще и сохраняет токен.
- **Отдельный токен для переноса.** Отклонено: не даёт выгоды; один capability на «управление бронью» достаточно.
- **Перенос только организатором из `/dashboard`.** Отклонено как единственный путь: спека просит ссылку для гостя; организатору панель/отмена доступны отдельно.
- **Мягкое удаление старой брони + новая (`status`).** Отклонено: статусов в модели нет, а `UNIQUE(slotId)` требует освободить старый слот (см. ADR-0005/0006).
