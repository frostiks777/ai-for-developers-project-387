# ADR 0026: Email-уведомления (Brevo HTTP API, ленивые напоминания)

## Status

Accepted — 2026-09-29. Связанные: [#83](https://github.com/frostiks777/ai-for-developers-project-386/issues/83), [`docs/research/email-notifications.md`](../research/email-notifications.md).

## Context

Нужны уведомления гостю (подтверждение, отмена, перенос, напоминание за 24 ч) и организатору (новая бронь, отмена). Ограничения задал пользователь: **бесплатно в учебных целях** и **не улететь в спам/бан**. Исследование провайдеров и ограничений Render — в `docs/research/email-notifications.md`; ключевое:

- **Render Free блокирует исходящий SMTP** (порты 25/465/587, с 26.09.2025) → отправка только через HTTPS API.
- **Render Cron Jobs платные** (от $1/мес), а free-сервис **засыпает через 15 минут простоя** → `setInterval`-планировщик ненадёжен.
- Своего домена у проекта **нет**: shared-песочница Resend шлёт только владельцу аккаунта (403), для писем гостям нужен домен с SPF/DKIM.
- Паттерн проекта: фича выключена, пока не задан ключ (как CAPTCHA, `server/captcha.ts`); тесты/CI/e2e не ходят в сеть.

## Decision

1. **Провайдер — Brevo HTTP API** (`POST https://api.brevo.com/v3/smtp/email`), free 300 писем/день. Отправка без своего домена: верифицируется один sender-email. Новых зависимостей нет — вызов через глобальный `fetch` (как в `server/captcha.ts`).
2. **Включение — по ключу:** `EMAIL_API_KEY` пуст → отправка no-op (`{ ok: true, skipped: true }`), в лог — один warn. Добавляются env: `EMAIL_API_KEY`, `EMAIL_FROM`, `EMAIL_REPLY_TO`, `ORGANIZER_EMAIL`, `REMINDER_LEAD_MINUTES` (по умолчанию 1440), `REMINDERS_SECRET`, `APP_ORIGIN`.
3. **Письма v1:** гостю — подтверждение, перенос, отмена, напоминание; организатору (на `ORGANIZER_EMAIL`) — новая бронь и отмена. Тексты — `text` + `html`, ссылка управления встречей в каждом письме, `Reply-To` организатора.
4. **Отправка синхронна в HTTP-хендлере** (создание/отмена/перенос) и не влияет на ответ: ошибка провайдера логируется, бронь не откатывается.
5. **Напоминания — ленивая проверка** (`server/reminders.ts`): выборка подтверждённых броней со `startAt` в ближайшие `REMINDER_LEAD_MINUTES` и `reminderSentAt IS NULL`, отправка и простановка `reminderSentAt` (идемпотентно). Триггеры: при старте сервера и throttle-проверка в `onRequest`; внешний бесплатный cron (cron-job.org) дёргает защищённый `POST /api/internal/reminders` с секретом `REMINDERS_SECRET` (сравнение timing-safe; секрет не задан → endpoint выключен).
6. **Схема БД:** `bookings.reminderSentAt` (nullable) — идемпотентный `ALTER TABLE ... IF NOT EXISTS` в `server/db/migrate.ts` + Drizzle-схема.
7. **Тесты/CI/e2e — без сети:** при пустом ключе всё no-op; для проверки шаблонов и вызовов `fetch` стабится (как в тестах CAPTCHA). Ручной dev-предпросмотр — Ethereal/Mailtrap (локальный `.env`, в git не попадает).

## Consequences

**+**
- Полностью бесплатно, без карты и без своего домена; SMTP-блокировка Render не мешает.
- Фича инертна без ключа: dev, `npm test`, CI и e2e не зависят от внешнего сервиса.
- Идемпотентные напоминания и отсутствие состояния планировщика в памяти — переживают сон/рестарт Render.
- Ноль новых зависимостей.

**−**
- Free-письма Brevo содержат бейдж «Sent with Brevo»; доставляемость без домена/SPF/DKIM ниже, чем у Resend — риск спам-папки.
- Напоминания неточны: точность ограничена частотой внешнего cron (±10–15 мин) и требуют настроенного cron-job.org (третий сервис).
- `ORGANIZER_EMAIL` один на инсталляцию (у `hosts` нет email) — per-host уведомления отложены.
- Ленивая проверка без внешнего пинга не сработает в простое (сервис спит).

## Alternatives considered

- **Resend (HTTP API)** — лучше free (3000/мес) и DX, но требует верифицированный домен для писем гостям; домена нет → отложено до появления домена (легко мигрировать: тот же `server/email.ts` + другой транспорт).
- **Mailjet** (6000/мес) — лимит 1000 контактов, логотип, очередь до 3 суток при превышении дневного лимита (губительно для напоминаний).
- **SMTP2GO** — без верификации домена жёсткий лимит 25 писем/час.
- **SendGrid / Amazon SES / Gmail SMTP** — нет постоянного free / нужна карта / SMTP заблокирован Render + риск бана аккаунта.
- **Render Cron Jobs** — платно (от $1/мес), противоречит constraint «бесплатно».
- **GitHub Actions schedule** — бесплатно, но задержки/дропы и авто-отключение триггера после 60 дней без активности репозитория; cron-job.org точнее и заодно будит сервис.
- **In-process `setInterval`** — теряется при сне/рестарте Render.
