# ADR 0002: Валидация API-контракта через zod

## Status

Accepted — 2026-09-22.

## Context

По спеке (`docs/code_artifact.md`) поле `email` обязательно в форме бронирования, при этом до этого тело `POST /api/bookings` проверялось вручную набором `typeof`-условий в `server/index.ts`. Ручная валидация не масштабируется: каждая новая проверка — это ещё одно условие, дублирование логики между формой и API и риск расхождения фронта и бэка. Кроме того, ошибки нужно показывать пользователю в читаемом виде (например, «Неверный email»).

## Decision

Для валидации API-контракта используется **zod 4**.

- Схема `createBookingSchema` описана в `server/validation.ts`, её зеркало для фронтенда — `src/lib/validation.ts` (тот же паттерн, что и у типов: `server/types.ts` ↔ `src/types/booking.ts`, менять только согласованно).
- На бэкенде маршрут `POST /api/bookings` вызывает `safeParse`; при ошибке возвращается `400` с сообщением первой ошибки.
- На фронтенде `BookingDialog` использует ту же схему: кнопка отправки активна только при валидной форме, для email показывается inline-ошибка.
- Правило email — встроенный валидатор zod (`z.email()`), без собственных regex.
- Правило телефона — `refine`: разрешены цифры и разделители (`+`, пробел, `-`, скобки), 10–15 цифр (E.164).

## Consequences

- (+) Декларативные проверки: одна схема описывает все поля и сообщения об ошибках.
- (+) Единое поведение фронта и бэка — одна и та же схема (пусть и зеркальная).
- (+) Из схемы при необходимости можно выводить типы (`z.infer`), меньше ручной синхронизации.
- (-) Новая зависимость; zod попадает и в клиентский бандл (~25 kB gzip — см. `npm run build`).
- (-) Схема физически дублируется в двух файлах; расхождение ловится тестами, но не компилятором.
- (-) Ручные проверки `typeof` заменены — поведение `400` сохранилось, но сообщения об ошибках изменились.

## Alternatives considered

- **Ручная валидация (`typeof`-условия).** Отклонено: дублирование между формой и API, растёт с каждым новым полем, сообщения об ошибках нестандартны.
- **JSON Schema + встроенный ajv Fastify.** Отклонено: работает только на сервере, на клиенте схему пришлось бы писать заново; менее выразительные сообщения об ошибках.
- **Библиотека `validator`.** Отклонено: набор строковых валидаторов без составных схем и типизации объекта целиком.
