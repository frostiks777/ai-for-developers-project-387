# ADR 0001: Record architecture decisions

## Status

Accepted — 2026-09-22.

## Context

Мы хотим сохранять важные архитектурные решения вне контекста диалога AI-агента, чтобы решения переживали `/compact`, смены сессии и смены моделей. Без долгосрочного хранилища каждое новое обсуждение начинается с нуля — агенту приходится реверс-инжинирить проект через код и `git log`, что занимает токены и приводит к несогласованным решениям.

## Decision

Все значимые архитектурные решения фиксируются в `docs/adr/NNNN-<slug>.md` по шаблону `docs/adr/template.md`. Каждый новый ADR добавляется в индекс (`docs/adr/README.md`). Решение об использовании ADR само по себе фиксируется этим документом (bootstrap-ADR по Nygard'у).

## Consequences

- (+) Решения не теряются при перезапуске сессии агента.
- (+) Новые участники/агенты читают ADR за минуты вместо реверс-инжиниринга через код.
- (+) Отклонения от спеки (`docs/code_artifact.md`) видно явно и обоснованно.
- (-) Дополнительная бюрократия: писать ADR захочется не всегда. Смягчение — порог «когда писать / когда НЕ» в README.
- (-) ADR могут устаревать и конфликтовать друг с другом; нужно явно отмечать `Deprecated` / `Superseded`.

## Alternatives considered

- **Хранить ADR в `MEMORY.md`.** Отклонено: перемешивает текущее состояние проекта и архитектурные решения, затрудняет обзор.
- **Не хранить вообще.** Отклонено: приводит к «забытым» решениям и повторению одних и тех же дискуссий.
- **Хранить в комментариях PR.** Отклонено: не индексируется единым списком и теряется при архивации репозитория.
