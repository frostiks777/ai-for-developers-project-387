# ADR 0012: Контракт-тесты (ajv) и e2e Playwright как отдельный гейт

## Status

Accepted — 2026-09-24.

## Context

Спецификация (`docs/spec.md` §7) и решение тикета [#14](https://github.com/frostiks777/ai-for-developers-project-386/issues/14) требуют трёх уровней проверки: API-интеграционные (Vitest + `app.inject()`), UI (RTL + jsdom) и сквозной сценарий в браузере. Дополнительно нужно автоматически проверять, что реализация не разошлась с контрактом `api/main.tsp` → `docs/openapi/openapi.yaml`.

Контракт и реализация исторически разошлись: `/api/v1/hosts/:slug/settings` отдавал поле `timezone` (строчная) и `availability`, `Booking` не содержал обязательный по контракту `timeZone`, а optional-поля (`clientPhone`, `clientNotes`, `description`, `date`) в реальности приходили как `null`.

## Decision

1. **Источник истины — контракт.** Расхождения устраняются правкой сервера под OpenAPI, а не ослаблением контракта; optional-поля, для которых сервер отдаёт `null`, помечены в TypeSpec как `?: <type> | null` и перегенерированы (`npm run api:generate`).
2. **Контракт-тесты** (`server/contract.test.ts`, уровень API-интеграционных): по `docs/openapi/openapi.yaml` проверяются (а) регистрация всех маршрутов `/api/v1/*` в Fastify (`app.hasRoute`) и (б) валидность ключевых ответов (настройки, слоты, бронь) через `ajv` + `ajv-formats`. `nullable: true` (OpenAPI 3.0) перед валидацией конвертируется в JSON Schema `anyOf: [..., { type: 'null' }]`.
3. **E2E Playwright** — отдельный гейт `npm run test:e2e`, не входит в `npm test` и в CI. Гоняется против **собранного** приложения: `webServer` выполняет `npm run build && npm start` на `:3100` с `DATABASE_PATH=:memory:` (каждый прогон — чистое состояние). Сценарии: сквозной путь гостя (тип → слот → форма → подтверждение) и конфликт слотов (повторная бронь того же слота, в т.ч. другим типом → `409 SLOT_TAKEN`).
4. Браузеры ставятся вручную: `npx playwright install chromium`; `.github/workflows/hexlet-check.yml` не трогаем.

## Consequences

- (+) Расхождения контракта и реализации ловятся автотестом до ревью.
- (+) Сквозной сценарий проверяется в реальном браузере; конфликт слотов покрыт на уровне HTTP.
- (+) e2e не замедляет `npm test` и не требует браузеров в CI.
- (−) Появляются devDependencies `ajv`, `ajv-formats`, `yaml`, `@playwright/test` и локальная установка Chromium (~115 МБ).
- (−) Тест валидирует только ключевые ответы, а не все маршруты/статусы (полная рантайм-валидация отклонена как избыточная).
- (−) `LocalDateTime` в контракте (локальное время без смещения) пока фактически несёт UTC ISO; формат ajv не проверяется, вопрос вынесен в сверку спецификации (T9, #27).

## Alternatives considered

- **Полная рантайм-валидация ответов** (middleware на сервере) — отклонена: лишний оверхед и связность, при этом курс требует лишь проверку ключевых ответов.
- **Ослабить контракт под текущую реализацию** — отклонена: Design First, контракт должен быть источником истины.
- **E2E против dev-серверов Vite + Fastify** — отклонена: два origin/proxy усложняют сценарий; сборка ближе к проду.
- **E2E в CI (`ci.yml`)** — отложено: отдельный гейт по решению #14; CI не должен тянуть браузеры.
