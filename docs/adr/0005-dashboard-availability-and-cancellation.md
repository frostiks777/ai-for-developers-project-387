# ADR 0005: Панель организатора — персистентные правила доступности и отмена брони

## Status

Accepted — 2026-09-23.

## Context

Спека (`docs/code_artifact.md`, §3 «Экран 4») требует панель организатора `/dashboard`: список запланированных встреч с отменой и вкладку «Настройки доступности» (рабочие дни, окно, длительность слота, буфер). До этого решения:

- правила доступности были захардкожены в коде ([ADR-0004](0004-slot-generation-rules.md)) — изменить расписание можно только деплоем;
- отмены брони не было вообще;
- `GET /api/bookings` был реализован, но UI-потребителя не имел;
- фронтенд был одностраничным (`App.tsx` → `HomePage`), без маршрутизации.

## Decision

Реализовать `/dashboard` в существующей однохостовой модели, без мульти-хостинга и авторизации.

- **Персистентные правила.** Новая таблица `availability_rules` — **одна строка с фиксированным `id = 1`** (MVP: один организатор). Поля повторяют `AvailabilityRules`; `weekdays` хранится JSON-массивом. `server/rules.ts`: `loadAvailabilityRules()` (fallback — `defaultAvailabilityRules` из ADR-0004), `saveAvailabilityRules()` (upsert), `regenerateFutureSlots()`.
- **API.** `GET /api/availability` и `PUT /api/availability` (валидация zod-схемой `availabilityRulesSchema`), `DELETE /api/bookings/:id`. Вариант `hosts` + `/api/v1/hosts/:slug/...` из спеки не реализуется: нет второго хоста, а версионирование и slug — цена без потребителя.
- **Перегенерация при смене правил.** Свободные будущие слоты удаляются, недостающие по новым правилам (в пределах горизонта и `minNotice`) добавляются. **Занятые слоты не трогаются**: на них ссылаются брони и `UNIQUE(slotId)` ([ADR-0003](0003-unique-slot-booking.md)). `GET /api/slots` и `POST /api/bookings` читают `minNotice` из сохранённых правил (а не из константы).
- **Отмена брони.** `DELETE /api/bookings/:id` удаляет строку брони; слот остаётся в `slots` и снова становится свободным (`isBooked` вычисляется join-ом). `204` при успехе, `404` при отсутствии, `400` при некорректном id.
- **Маршрутизация.** `react-router-dom` (`BrowserRouter` в `main.tsx`, `Routes` в `App.tsx`): `/` — гость, `/dashboard` — организатор. Авторизации нет (учебный вариант).
- **UI.** `DashboardPage` (загрузка/ошибки/состояния), `BookingsTable` (таблица + кнопка отмены), `AvailabilityForm` (чекбоксы дней, числовые поля, zod-валидация до отправки). Зеркала типов и zod-схем — как обычно.

## Consequences

- (+) Расписание меняется через UI, без деплоя; правила совпадают с генерацией и лид-таймом.
- (+) Отмена освобождает слот и не ломает `UNIQUE(slotId)`; занятые слоты переживают смену правил.
- (+) Контракт API не версионируется — новые эндпоинты в `/api`, как остальные.
- (−) Таблица `availability_rules` однохостовая (`id = 1`): при появлении `hosts` потребуется миграция схемы и переход на `/api/v1/hosts/:slug/...`. Отклонение от спеки зафиксировано здесь и в `docs/todo.md`.
- (−) Нет авторизации — `/dashboard` публично доступен. Для учебного MVP допустимо, для продакшена недопустимо.
- (−) Перегенерация пересоздаёт свободные слоты: их `id` меняются. Стабильность `id` нужна только занятым слотам (броням), их не трогаем. Внешних ссылок на свободные слоты нет.
- (−) Окно доступности — общее на все рабочие дни (одна пара start/end), тогда как спека допускает разные диапазоны по дням. Матрица «по дню» отложена.

## Alternatives considered

- **Полная hosts-модель (`hosts` + `availability_rules` с `host_id`, `/api/v1`).** Отклонено: мульти-хост не нужен MVP; тянет существенную схему, версионирование API и auth-заглушку ([`docs/archive/archi-scheme.md`](../archive/archi-scheme.md) №9–10 рекомендует отложить).
- **Мягкое удаление брони (`status = 'cancelled'`).** Отклонено для MVP: в существующей модели статусов нет, а `UNIQUE(slotId)` не даст перебронировать слот со «отменённой» строкой. Потребовало бы `UNIQUE ... WHERE status != 'cancelled'` (partial index) — сознательно отложено.
- **Хранить правила глобальной переменной в памяти.** Отклонено: на Render процесс перезапускается, настройки терялись бы; персистентность — базовая ожидаемая функция настроек.
- **Правки только через код/деплой (как ADR-0004).** Отклонено: цель панели — управление без деплоя.
- **Другой роутер (TanStack Router) или хэш-навигация.** Отклонено: `react-router-dom` — стандарт, минимальная настройка для двух маршрутов; хэш-навигация менее канонична и хуже для прямой ссылки `/dashboard`.
