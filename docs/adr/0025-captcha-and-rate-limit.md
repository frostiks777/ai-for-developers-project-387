# ADR-0025: Защита публичной записи — Cloudflare Turnstile и rate-limit по IP

## Status

Accepted — 2026-09-28. Закрывает [#46](https://github.com/frostiks777/ai-for-developers-project-386/issues/46).

## Context

`POST /api/v1/hosts/:slug/bookings` публичен, а тело принимает произвольные email гостей
([ADR-0015](0015-booking-guests-consent-idempotency.md)). Форму можно автоматизировать: спам-брони,
захват слотов, рассылка приглашений на произвольные адреса. Собственный rate-limit по IP в проекте
отсутствовал, `trustProxy` не был настроен.

Ограничения, определившие решение:

- **Деплой** — Render Web Service, план `free`, `frankfurt`, `calendar-slots-app.onrender.com`
  ([docs/ci_cd_render.md](../ci_cd_render.md)). Один инстанс, засыпает после ~15 минут простоя.
  Перед приложением — Cloudflare (его edge), своего Cloudflare-зона у проекта нет.
- **CI** содержит job `e2e` с Playwright ([ADR-0012](0012-contract-tests-and-e2e.md)) и ~15 наборов
  Vitest, включая контракт-тест по OpenAPI. Внешняя зависимость в тестах = источник флаков.
- **Контракт API** описан в TypeSpec (`api/main.tsp`) и генерируется в OpenAPI + клиентский SDK +
  серверные типы (`npm run api:generate`, [ADR-0011](0011-event-types-status-and-availability-ranges.md)).
  Ошибки уже имеют машиночитаемый код (`ErrorCode`), но `src/api/sdk.ts` его отбрасывал.

## Decision

1. **Провайдер — Cloudflare Turnstile, бесплатный план, режим Managed, Visible, Pre-clearance Off.**
   На Free: безлимитные челленджи и верификации, до 20 виджетов и 10 хостов на виджет.
   Работает standalone, без Cloudflare перед приложением (значит, не зависит от того, что мы не
   управляем своим CF-зоной).

2. **CAPTCHA выключена, пока не задан `TURNSTILE_SECRET_KEY`.** Единственная точка включения —
   `server/captcha.ts` (`isCaptchaEnabled()`). Пока секрет не задан:
   - `GET /api/v1/hosts/:slug/settings` отдаёт `captcha: { provider, required: false, siteKey: null }`;
   - форма не рендерит виджет и не грузит скрипт Cloudflare;
   - сервер не проверяет токен.
   Локальный dev, `npm test` и Playwright-e2e в CI не зависят от внешнего сервиса, а существующие
   тесты не требуют правок. В `NODE_ENV=production` без секрета приложение пишет
   `app.log.warn` на старте, но **не падает** — тем же приёмом, что `ADMIN_PASSWORD` в
   [ADR-0017](0017-dashboard-basic-auth.md). Жёсткий fail-fast отклонён как ломающий деплой.

3. **Site key фронтенду отдаёт `GET /api/v1/hosts/:slug/settings`** полем `captcha: CaptchaSettings`
   (модель в `api/main.tsp`). Страница записи делает третий параллельный запрос, как и за
   availability/event-types. Отклонён `VITE_TURNSTILE_SITEKEY`: в проекте не использовался ни один
   `import.meta.env`, а конфиг запекался бы на этапе сборки.

4. **Проверка токена — в обработчике `POST /api/v1/hosts/:slug/bookings`, порядок шагов:**
   реплей по `Idempotency-Key` → разбор тела (zod) → CAPTCHA → бизнес-логика слотов.
   - Реплей идёмпотентности идёт **первым**: токен Turnstile одноразовый, повторная верификация
     израсходованного токена вернула бы ложный `CAPTCHA_FAILED`.
   - CAPTCHA **после** zod, но **до** слотов: мусорный запрос не должен стоить сетевого вызова.
   - Ошибка — `422 { error: { code: 'CAPTCHA_FAILED' } }` (код добавлен в `ErrorCode`).
   - Легаси `POST /api/bookings` тоже проверяет опциональный токен, иначе он был бы очевидным
     обходом. Он не входит в контракт OpenAPI, регенерация не требуется.

5. **`server/captcha.ts` — fail-closed.** Таймаут 5 с (`AbortSignal.timeout`), `remoteip` = `request.ip`,
   передаётся `idempotency_key`. Недоступность Cloudflare, не-2xx и `success: false` равнозначны
   `CAPTCHA_FAILED` — кратковременный сбой внешнего сервиса не должен открывать ботнет.
   Сверка `hostname` из ответа включается только для реального секрета (не dummy) и только если
   задан `TURNSTILE_ALLOWED_HOSTNAMES`.

6. **Виджет показывается всегда**, а не только при заполненных «Гостях». Вектор абьюза не только в
   `guests`: сам эндпоинт позволяет занимать слоты и слать письма на основной email клиента.
   Один код-путь проще и дешевле поддерживать.

7. **Rate-limit — `@fastify/rate-limit` (≥10, совместим с Fastify 5), in-memory LRU.**
   `global: false` + лимиты на маршрутах, общий предохранитель 600/мин:
   | Что | Лимит |
   |---|---|
   | создание брони (v1 + легаси) | 20/мин |
   | отмена и перенос (v1 + легаси) | 20/мин |
   | публичные чтения (slots, availability, event-types, settings) | 300/мин |
   | всё остальное | 600/мин |
   Ответ 429 собирается в общем конверте ошибок: `{ error: { code: 'RATE_LIMITED', message } }`
   (`RATE_LIMITED` добавлен в `ErrorCode`, 429 — в returns операции в TypeSpec).
   Значения читаются из env (`RATE_LIMIT_BOOKING_MAX` и др.) **лениво**, с боевыми дефолтами:
   наборы тестов поднимают их до несущественности вместо того, чтобы подгонять прод под тесты.

8. **Определение IP клиента — `server/rate-limit.ts: clientIpKey`.** Приоритет у
   `CF-Connecting-IP` (Cloudflare перезаписывает его настоящим адресом клиента, клиентское
   значение не проходит), иначе `request.ip` при `trustProxy: true`.
   Без `trustProxy` у всех гостей `request.ip` одинаков (адрес прокси) и лимит становится
   **глобальным** — один спамер заблокировал бы всех. Отклонён подбор «числа доверенных прокси»:
   `proxy-addr` дописывает адрес сокета к `X-Forwarded-For`, поэтому фактическая глубина цепочки
   на Render — 3 хопа, а не 2, и любая жёстко заданная цифра молча ломает лимит (поймано тестом).

9. **Клиент виджета — свой код без зависимости** (`src/hooks/use-turnstile.ts`): скрипт
   `challenges.cloudflare.com/turnstile/v0/api.js?render=explicit`, промис-кэш на загрузку,
   `turnstile.render/reset/remove`. Отклонён `@marsidev/react-turnstile` ради ~30 строк.
   `ApiError` теперь несёт `code` из тела ответа — без него форма не отличает `CAPTCHA_FAILED`
   от обычного `422 VALIDATION_ERROR` (форма показывает текст ошибки по месту, тост подавлен).

## Consequences

**+** Бесплатно и безлимитно, без своей инфраструктуры и без нового аккаунта.
**+** Один переключатель (`TURNSTILE_SECRET_KEY`) включает и выключает всю защиту разом.
**+** CI и e2e не зависят от Cloudflare: у Turnstile есть официальные dummy-ключи
  (`1x00000000000000000000AA` / `1x0000000000000000000000000000000AA`), а тесты всё равно идут
  с выключенной каптой.
**+** Rate-limit закрывает не только форму, но и прямые POST в API.
**+** `ApiError.code` и `RATE_LIMITED`/`CAPTCHA_FAILED` в контракте пригодятся дальше.
**?** IP гостя уходит в Cloudflare (US). Для MVP/course-проекта приемлемо; при реальном трафике и
  требовании 152-ФЗ решение пересматривается (см. альтернативы).
**?** Логин/подбор хоста: `GET /api/v1/hosts` отдаёт список хостов гостю (уже было до этого
  решение), капча его не защищает.
**?** In-memory счётчики: после холодного старта Render обнуляются (для MVP приемлемо), при
  нескольких инстансах лимит нужно делить — потребуется Redis/Upstash.
**?** `trustProxy: true` доверяет `X-Forwarded-For`; безопасно, пока приложение живёт за
  Cloudflare, который этот заголовок перезаписывает. Смена платформы ⇒ пересмотреть.
**?** `TURNSTILE_ALLOWED_HOSTNAMES` надо задать в Render, иначе сверка домена не включена.

## Alternatives considered

- **hCaptcha** (вариант из #46) — отклонён. Бесплатный план = всегда видимый чекбокс
  «Я не робот», а invisible/passive-режим и аналитика только в Pro за $99–139/мес. Для формы
  записи, где важна конверсия, хуже Turnstile Managed.
- **Yandex SmartCaptcha** — отклонён на текущем этапе. Плюсы: RU-резидентность (152-ФЗ),
  цена $0.90 за 1 000 запросов после бесплатных 10 000/мес. Минусы: нужен аккаунт Yandex Cloud с
  биллингом, **нет документированных тестовых ключей** — а это ломает e2e-гейт в CI. Вернуться к
  нему при появлении требования по резидентности или реального трафика.
- **Self-host ALTCHA / Cap** — отклонены. Плюсы: приватность, полный контроль. Минусы: нужен
  отдельный сервис в проде, а proof-of-work без бот-оценки слаб именно против целевого бота,
  автоматизирующего форму.
- **Cloudflare WAF / rate-limiting** — отклонено: у проекта нет своего CF-зоны (Render со своим
  edge), так что правила пришлось бы настраивать на чужом аккаунте.
- **Только honeypot + timestamp без внешнего сервиса** — отклонено как единственная мера: не
  останавливает прямые POST в API в обход формы.
- **Fail-open при недоступности Cloudflare** — отклонено сознательно: сбой внешнего сервиса
  превращался бы в окно для спама ровно тогда, когда боты активнее всего.
- **Жёсткий падёж в production без `TURNSTILE_SECRET_KEY`** — отклонено: конфигурационный
  недочёт Render не должен ронять деплой. Вместо этого `log.warn`.
