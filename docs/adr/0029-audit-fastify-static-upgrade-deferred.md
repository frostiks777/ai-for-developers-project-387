# ADR 0029: Аудит зависимостей — обновление @fastify/static до 10.x отложено

## Status

Accepted — 2026-09-29. **Апгрейд выполнен в тот же день** ([#99](https://github.com/frostiks777/ai-for-developers-project-386/issues/99)): см. раздел «Update». Имя файла оставлено прежним, чтобы не ломать ссылки в issue и в индексе.

## Context

Ревью проверяющего (2026-09-29) потребовало разобрать вывод `npm audit` и обновить
безопасно обновляемые зависимости, не применяя автоматически ломающие изменения
(issue #91). Транзитивные находки по `undici` тогда сняли обновлением
`@scalar/json-magic` (`b44c82a`), и `npm audit` упал с 7 до 5 находок.

Оставшиеся 5 находок — два независимых пакета.

### 1. `@fastify/static` — high, прямая зависимость

Установлена `^8.3.0`, фактически `8.3.0`. На неё приходится четыре advisory:

| Advisory | Severity | Затронутый диапазон |
| --- | --- | --- |
| [GHSA-83w8-p2f5-377r](https://github.com/advisories/GHSA-83w8-p2f5-377r) — path traversal | **high** (CVSS 7.5) | `<=10.1.0` |
| [GHSA-8pvw-jcv7-9cmj](https://github.com/advisories/GHSA-8pvw-jcv7-9cmj) — Authorization Bypass через неканонический URL | moderate | `<=10.1.1` |
| [GHSA-x428-ghpx-8j92](https://github.com/advisories/GHSA-x428-ghpx-8j92) — route guard bypass через закодированные разделители | moderate | `>=8.0.0 <=9.1.0` |
| [GHSA-pr96-94w5-mx2h](https://github.com/advisories/GHSA-pr96-94w5-mx2h) — path traversal в листинге каталога | moderate | `>=8.0.0 <=9.1.0` |

Патчей в ветке 8.x нет: 8.3.0 — последний релиз восьмой ветки, и он же попадает
в диапазон `<=10.1.1`. Единственная исправленная версия — **10.1.5**, то есть
`npm audit fix --force` предлагает переход `8.3.0 → 10.1.5` (мажор, два пропущенных
минорных релиза). Поэтому «обновить безопасно обновляемое» здесь невозможно в
буквальном смысле: либо мажорный апгрейд, либо оставить high-находку.

### 2. `esbuild` — moderate, только dev-CLI

Тянется `drizzle-kit@0.31.11` → `@esbuild-kit/esm-loader` → `@esbuild-kit/core-utils`
→ `esbuild@0.18.20` ( Advisory [GHSA-67mh-4wv8-2f99](https://github.com/advisories/GHSA-67mh-4wv8-2f99),
диапазон `<=0.24.2`). `npm audit fix --force` предлагает **понизить** `drizzle-kit`
до `0.18.1` — это не обновление, а откат на версию старше текущей ORM-тулинга.
В прод-сборку пакет не попадает: `drizzle-kit` нужен только для `db:generate` /
`db:push`, а реальные миграции выполняет идемпотентный `server/db/migrate.ts`
([ADR-0013](0013-postgres-migration.md)).

## Decision

1. **`@fastify/static` не обновляем сейчас.** Помечаем как осознанный долг и
   берём в бэклог: переход на `10.1.5` — отдельная задача с прогоном
   `lint`/`typecheck`/`test`/`build`/e2e и ручной проверкой раздачи `dist/`.
2. **Оценка риска при текущей версии.** Плагин включается только при наличии
   каталога `dist/` (`server/app.ts`, регистрация `{ root: distDir, prefix: '/' }`).
   Риск ограничен самой раздачей статики: листинг каталогов не включался
   (`serve: true` не задан), `setHeaders` не используется, авторизация статикой
   не защищается — её нет вовсе ([ADR-0028](0028-dashboard-access-without-login.md)).
   То есть вектор «Authorization Bypass» и «route guard bypass» здесь не
   эксплуатируемы, а path traversal ограничен пределами `dist/`.
3. **`drizzle-kit`/`esbuild` не трогаем.** Находка moderate, затрагивает только
   dev-инструмент вне контейнера; «фикс» — откат версии, что хуже самой находки.
4. **Правило на будущее:** обновления безопасности, требующие мажорного апгрейда,
   не применяются «втихую» — оформляются как issue с обоснованием и планом.

## Update (2026-09-29): апгрейд выполнен

Долг закрыт через день, отдельной задачей [#99](https://github.com/frostiks777/ai-for-developers-project-386/issues/99) по плану из 9 шагов. Разбор цепочки 8 → 10 подтвердился на практике.

**Что сделано:**

1. **Baseline снят до апгрейда** (локальная прод-сборка, `PORT=3210 DATABASE_URL= npm start`): статусы, `Content-Type`, `Content-Length` по `/`, `/assets/*`, `/dashboard`, `/health`, `/api/v1/*`, плюс пробы обхода каталога. Зафиксирован в [#99 (comment)](https://github.com/frostiks777/ai-for-developers-project-386/issues/99).
2. **Установлено `@fastify/static@^10.1.5`** обычным `npm i`, без `npm audit fix --force` (тот откатил бы `drizzle-kit` до `0.18.1`).
3. **Кода приложения не потребовалось**: обе точки касания (`register(fastifyStatic, { root, prefix })` и `reply.sendFile('index.html')`) не затронуты ни одним ломающим изменением. `typecheck`/`lint` — чисто без единой правки.
4. **Тесты:** 331/331 до, `npm run test:e2e` — 3/3 (Playwright против `build && start`), то есть реальная раздача и SPA-fallback проверены браузером.
5. **Сверка с baseline:** все статусы и `Content-Type` совпали; прод-бандл `dist/assets/index-*.js` побайтово тот же (155.52 kB). `glob` 11 → 13 в рантайме не проявился.
6. **`npm audit`:** `high`-находка по `path traversal` ушла; остались 4 `moderate` по `esbuild` через `drizzle-kit` — dev-only, п. 3 Decision остаётся в силе.
7. **Закрыта дырка в покрытии:** добавлен `server/static.test.ts` (5 тестов, `describe.skipIf(!hasBuild)`): `/` и `/dashboard` → 200 html, `/assets/` без листинга, обход через `%2e%2e%2f` не выпускает файлы за пределы `dist/`, `/health` не перехватывается статикой. В `.github/workflows/ci.yml` шаг `Build` перенесён **перед** `Test`, иначе дист в CI отсутствует и тест молча скипается.

**Выводы для будущих мажорных апгрейдов:** проверять не только API плагина, но и его транзитивные зависимости (`glob`), и обязательно иметь baseline раздачи — юнит-тесты Fastify работают через `inject` и статику не покрывают, её ловит только e2e.

## Consequences

**+** Решение зафиксировано: следующий, кто увидит `npm audit` в 5 находках,
найдёт ответ в этом ADR и в issue, а не будет разбираться заново.
**+** Требование ревью выполнено: аудит разобран, обновлено всё, что обновляется
безопасно (`undici` → `@scalar/json-magic`), ломающие изменения не применены.
**+** Риск `high` в `@fastify/static` оценён и понятен: эксплуатируемость
в текущей конфигурации приложения низкая.
**−** `high`-находка остаётся в отчёте `npm audit`, пока не будет сделан
мажорный апгрейд. Это осознанный долг, а не «забыто».
**−** Следующий `npm audit` в CI по-прежнему будет красным по этой находке —
проверки в `ci.yml` аудит не запускают, так что на зелёный CI это не влияет.

## Alternatives considered

- **Обновить `@fastify/static` до 10.1.5 сразу.** Отклонено как нецелесообразное
  на этом шаге: изменение затрагивает продакшн-раздачу `dist/` (единственный
  способ, которым пользователь видит приложение в Render), а требование ревью
  прямо запрещает применять ломающие изменения автоматически. Требует отдельного
  цикла проверки.
  Разбор цепочки 8 → 10 показал, что риск невысок и апгрейд безопасен делать
  осознанно позже: **v9.0.0** — только bump `content-disposition` и `glob@13`,
  кодовых ломающих изменений нет; **v10.0.0** — единственное ломающее изменение
  это `setHeaders`, которому теперь передаётся `FastifyReply` вместо `Response`,
  а мы его не используем; таблица совместимости плагина (`>=8.x` → Fastify `^5.x`)
  одинакова для 8 и 10, то есть мажор Fastify не требуется; `decorateReply`
  по умолчанию `true` в обеих ветках, поэтому `reply.sendFile('index.html')`
  в SPA-fallback продолжает работать. То есть фактических правок кода не нужно.
- **Оставить `npm audit fix --force` без разбора.** Отклонено: для `esbuild`
  команда означала бы откат `drizzle-kit` до `0.18.1`.
- **Убрать `@fastify/static` и раздавать `dist/` own-кодом.** Отклонено: своя
  реализация отдачи файлов — это новая поверхность для path traversal, то есть
  ровно тот класс уязвимости, который мы пытаемся закрыть.
- **Отключить аудит в CI.** Отклонено: скрыло бы находку, а не закрыло её.
