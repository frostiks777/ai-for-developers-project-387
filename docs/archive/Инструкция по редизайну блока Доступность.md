## 1. Цель задачи
Переработать текущий блок настройки расписания ("Доступность"), решив проблему избыточной вертикальной высоты и неудобного ввода одинаковых слотов для каждого дня.

Интерфейс должен следовать паттернам сервисов вроде Calendly/Cal.com:
- Компактный однострочный лейаут для каждого дня (Row Layout).
- Быстрые пресеты расписания (Quick Presets).
- Мгновенная валидация времени на лету (Real-time Validation).
- Индикация часового пояса внутри карточки.
- Возможность копирования расписания на другие дни (Bulk copy).

---

## 2. Анатомия компонента

Карточка делится на 4 логические зоны:
1. **Header (Шапка):**
   - Заголовок `Доступность`.
   - Подзаголовок: `Из этих правил собираются свободные слоты`.
   - **Индикатор таймзоны:** бейдж или строка с иконкой глобуса/часов: `Часовой пояс: Europe/Moscow` (таймзона берется из настроек профиля/браузера).
2. **Preset Chips (Быстрые пресеты):**
   - Горизонтальный ряд тегов/чипсов для применения типового графика в один клик:
     - `Пн–Пт, 10:00–18:00` (дефолтный)
     - `Пн–Пт, 09:00–18:00`
     - `Каждый день, 10:00–20:00`
     - `Очистить всё`
3. **Weekly Schedule List (Список дней недели):**
   - 7 строк (Пн, Вт, Ср, Чт, Пт, Сб, Вс).
   - Каждая строка отображается **в одну горизонтальную линию**.
4. **Footer / Actions (Подвал):**
   - Кнопка "Сохранить изменения" (если форма не сохраняется автоматически).
   - Информационная подсказка о пересечении слотов.

## 3. Спецификация строки дня (Single-Row Layout)

Каждая строка дня недели имеет фиксированную структуру `flex items-center gap-2`:

```text
[ Toggle / Switch ] [ Название дня (Пн) ] [ Start Time ] — [ End Time ] [ + Добавить ] [ ⎘ Копировать ] [ ✕ Удалить ]
```

### Состояния строки:

#### А. День выключен (Inactive / Off)
- Switch / Checkbox: `unchecked`.
- Название дня: полупрозрачное (`text-gray-400`).
- Поля времени скрываются или заменяются текстом: `Недоступен` (серый текст).
- Иконки `+` и `Копировать` скрыты или заблокированы.

#### Б. День активен (Active / On)
- Switch / Checkbox: `checked` (акцентный цвет, например `#14b8a6` / `#0f766e` под стиль интерфейса).
- Название дня: полужирное фиксированной ширины (например, `w-8` или `min-w-[32px]`).
- Блок интервала:
  - Input `startTime` (формат `HH:mm`, `10:00`).
  - Разделитель `—` или `до`.
  - Input `endTime` (формат `HH:mm`, `18:00`).
- Кнопка добавления интервала: компактная иконка `+` (вместо длинной текстовой кнопки).
- Кнопка копирования: иконка `Copy` (открывает тултип/поповер с выбором целевых дней).
- Кнопка удаления интервала: `✕` (доступна, если у дня больше 1 интервала, либо сбрасывает интервал).

#### В. Несколько интервалов в один день (например, с перерывом на обед)
- Первый интервал отображается на основной строке дня.
- Второй интервал переносится на следующую строку со сдвигом (на месте тумблера и названия дня — пустой отступ `indent`).
- Пример:
  ```text
  [✓] Пн   [ 10:00 ] — [ 14:00 ]   [ + ] [ ⎘ ] [ ✕ ]
           [ 15:00 ] — [ 19:00 ]               [ ✕ ]
  ```

## 4. Логика быстрых пресетов (Presets)

При клике на чипс пресета:
1. Запрашивать подтверждение только если пользователь уже вносил кастомные изменения, либо применять сразу с возможностью отмены (Undo toast).
2. Пример применения пресета `Пн–Пт, 10:00–18:00`:
   - Пн–Пт: `enabled: true`, `intervals: [{ start: "10:00", end: "18:00" }]`
   - Сб–Вс: `enabled: false`, `intervals: []`

## 5. Валидация на лету (Real-Time Validation)

Валидация должна срабатывать по событиям `onChange` / `onBlur` без перезагрузки:

1. **Проверка хронологии:**
   - Условие: `startTime < endTime`.
   - Если `startTime >= endTime`:
     - Подсветить рамку поля `endTime` красным (`border-red-500 bg-red-50`).
     - Вывести мини-подсказку под интервалом: *"Время окончания должно быть позже времени начала"*.
     - Заблокировать кнопку сохранения / отправку запроса.

2. **Проверка пересечения интервалов (Overlap check):**
   - Если для одного дня добавлено $\ge 2$ интервалов:
     - Интервалы не должны накладываться друг на друга (например, `10:00–14:00` и `13:00–16:00` недопустимы).
     - При конфликте подсвечивать оба конфликтующих поля с сообщением: *"Интервалы пересекаются"*.

3. **Минимальная длительность слота:**
   - Интервал не должен быть меньше минимальной длины активных типов встреч (например, если встреча 30 минут, интервал не может быть 15 минут).

## 6. Пример структуры данных (TypeScript Interface)

```typescript
export interface TimeInterval {
  id: string;
  start: string; // "10:00"
  end: string;   // "18:00"
  error?: string | null;
}

export type DayOfWeek = 'mon' | 'tue' | 'wed' | 'thu' | 'fri' | 'sat' | 'sun';

export interface DaySchedule {
  day: DayOfWeek;
  label: string; // "Пн", "Вт" и т.д.
  isEnabled: boolean;
  intervals: TimeInterval[];
}

export interface AvailabilitySettings {
  timezone: string; // e.g. "Europe/Moscow"
  schedule: DaySchedule[];
}
```
