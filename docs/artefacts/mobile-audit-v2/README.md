# Мобильный аудит после редизайна v2 (#49)

Прогон 2026-09-28 на собранном приложении (`npm run build && npm start`, `PORT=3100`, PGlite): **14 экранов × 2 ширины (360×800, 390×844) × 2 темы = 56 проверок**.

Метрики на каждом экране:

- `horizontalOverflow` — `document.scrollWidth − clientWidth` (горизонтальная прокрутка недопустима);
- `offenders` — элементы, вышедшие за правый край экрана (без учёта намеренно прокручиваемых контейнеров);
- `overlaps` — пары видимых интерактивных элементов, перекрывающих друг друга.

## Итог

**56/56 проверок чистые:** `horizontalOverflow = 0`, `offenders = 0`, `overlaps = 0` на всех экранах в обеих темах и на обеих ширинах.

Экраны: `landing`, `book`, `book-dialog`, `success` (заполненная бронь через UI), `my` (с подложенной записью в `localStorage`), `confirmed`, `manage-cancel`, `manage-reschedule`, `dashboard`, `dashboard-bookings`, `dashboard-availability`, `dashboard-hosts`, `dashboard-blocks`, `notfound`.

## Что починено в этом заходе

1. **Строка дня в форме доступности** (`/admin/availability`): поля времени были `w-[112px] shrink-0`, кнопки «+» и «копировать» уходили за правый край (53 px на 360 px, 23 px на 390 px). Теперь группа полей держит минимум 208 px и переносится целиком, кнопки строки переносятся на вторую строку и прижимаются вправо (`max-sm:ml-auto`), на десктопе раскладка не изменилась (`sm:`-варианты).
2. **Шапка секции «Блокировки»** (`/admin/blocks`): описание «Отпуск, личные дела…» сжималось в узкую колонку из 2–3 слов рядом с кнопкой. Теперь на мобильном описание и кнопка в столбике, на десктопе — в строку.

Регресс-тесты: `src/components/availability-settings-form.test.tsx`, `src/components/blocks-editor.test.tsx`.
