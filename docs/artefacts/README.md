# Мобильный аудит вёрстки - issue #49

Результаты прогонов мобильной версии (issue
[#49](https://github.com/frostiks777/ai-for-developers-project-386/issues/49)).

## Что здесь

- `Capture*.PNG` — скриншоты владельца (найдены вручную), в корне папки.
- `mobile-audit/` — **до v2** (2026-09-28, коммит `ee63b9e`): прогон Playwright/Chromium,
  9 маршрутов × 2 темы (light/dark) × 2 ширины (390×844, 360×800) + интерактивные состояния.
  Отчёт: `mobile-audit/report.json`, `report2.json`. Именно этот прогон открыл issue.
- `mobile-audit-v2/` — **после редизайна v2** (2026-09-28): 14 экранов × 2 темы ×
  2 ширины = 56 проверок, все чистые. Свой `README.md` с методикой и итогами.

## Найденные дефекты

Полный чек-лист с шагами воспроизведения и критериями — в issue
[#49](https://github.com/frostiks777/ai-for-developers-project-386/issues/49).

## Воспроизведение

```
npm run build && npm start
```

DevTools → responsive, ширина 390 и 360 px, обе темы; ландшафтная ориентация
для пунктов про шапку.

## Важно

Часть дефектов перекрывается редизайном v2
([#48](https://github.com/frostiks777/ai-for-developers-project-386/issues/48)):
шапка, мобильный мастер записи, экран успеха и панель переписываются на
этапах 3/6/7/10. Проверено повторным прогоном: после v2 остались только два
дефекта в панели организатора (`/admin/availability`, `/admin/blocks`) — оба
починены, см. `mobile-audit-v2/README.md`.

## Скрипты аудита

Временные Playwright-скрипты, которыми сняты скриншоты, **не коммитятся**
(удалены из корня репозитория). При необходимости их можно воспроизвести по
описанию в issue #49.

## Обновление списка

```
# из корня репозитория
npm run build && npm start
# затем прогнать сценарии из issue #49 и обновить mobile-audit/
```
